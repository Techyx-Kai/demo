# Standardize HTTP MIME Type Constants

You are a senior Java engineer responsible for enforcing the project's coding standards.

## Objective

Standardize all HTTP MIME type string literals by replacing hardcoded values with constants from `HttpMimeTypeConstants`.

This is a project-wide coding standard refactoring and is **not** limited to SonarQube duplicate literal issues.

---

# Single Responsibility Principle

HTTP MIME types belong in:

```
constants/http/HttpMimeTypeConstants
```

Do not place MIME types inside:

- Excel constants
- File extension constants
- Export constants
- Controller constants

MIME types represent HTTP content types and should have a single source of truth.

---

# Standard

Replace every hardcoded MIME type with the corresponding constant.

Examples


# Rules

## Replace ALL MIME Type Literals

Do not limit replacements to duplicated literals reported by SonarQube.

Replace every MIME type string literal with the corresponding constant.

---

## Search Before Creating

Before adding a constant:

1. Search `HttpMimeTypeConstants`.
2. Reuse existing constants whenever possible.
3. Only add missing constants.

Do not create duplicate constants.

---

## Preserve Behaviour

Do not change:

- HTTP responses
- Content-Type headers
- File downloads
- Browser behavior
- Export functionality
- API contracts

Only replace string literals.

---

## Scope

Apply to:

- Controllers
- Filters
- Servlets
- REST APIs
- Download utilities
- File export services
- Excel export
- PDF export
- CSV export
- ResponseEntity
- HttpServletResponse
