# Standardize HTTP Web Constants

You are a senior Java engineer responsible for enforcing the project's coding standards.

## Objective

Standardize all hardcoded HTTP-related string literals by replacing them with the appropriate enums under `enums/web`.

This is a **project-wide coding standard refactoring**, not just a SonarQube duplicate literal fix.

The generated code must remain **100% functionally equivalent**.

---

# Single Responsibility Principle

Do **not** create generic constants classes.

Each enum must have a single responsibility.

---

# HTTP Header Keys

HTTP header names belong in

```
enums/web/HttpHeaderKey
```

Examples

```java
Content-Type
Content-Disposition
Cache-Control
Pragma
Expires
Content-Length
Content-Encoding
Location
Accept
Authorization
User-Agent
```

Example

Before

```java
response.setHeader("Cache-Control", value);
```

After

```java
response.setHeader(
    HttpHeaderKey.CACHE_CONTROL.getKey(),
    value
);
```

---

# HTTP Header Values

Common HTTP header values belong in

```
enums/web/HttpHeaderValue
```

Examples

```java
public
private
no-cache
no-store
must-revalidate
max-age=0
attachment
inline
keep-alive
close
```

Example

Before

```java
response.setHeader("Pragma", "public");
```

After

```java
response.setHeader(
    HttpHeaderKey.PRAGMA.getKey(),
    HttpHeaderValue.PUBLIC.getValue()
);
```

Example

Before

```java
response.setHeader("Cache-Control", "max-age=0");
```

After

```java
response.setHeader(
    HttpHeaderKey.CACHE_CONTROL.getKey(),
    HttpHeaderValue.MAX_AGE_ZERO.getValue()
);
```

# Rules

## Replace ALL Hardcoded HTTP Literals

Replace every hardcoded

- HTTP header name
- HTTP header value
- MIME type

with the appropriate enum.

Do **not** limit replacements to duplicated literals reported by SonarQube.

---

## Search Before Creating

Before adding a new enum value

1. Search the destination enum.
2. Reuse existing enum values whenever possible.
3. Only add missing values.

Never duplicate constants.

---

## Preserve Behaviour

Do not change

- HTTP responses
- Content-Type
- Response headers
- Download behaviour
- Browser caching
- File names
- Response status
- Business logic
- Framework behaviour

Only replace string literals.

# Golden Rules

1. Follow the **Single Responsibility Principle**.
2. `HttpHeaderKey` is the single source of truth for HTTP header names.
3. `HttpHeaderValue` is the single source of truth for reusable HTTP header values.
4. `HttpMimeType` is the single source of truth for MIME types.
5. Reuse existing enum values before creating new ones.
6. Replace **all** hardcoded HTTP-related string literals, not only SonarQube duplicate literals.
7. Do not create generic constants classes.
8. Preserve 100% functional equivalence.
9. Keep changes minimal and follow the project's existing architecture and coding standards.
